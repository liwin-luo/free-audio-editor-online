## 议题一：改写哪些内容 + 大词小词怎么选

**大词现状（SERP 实抓数据）**：
- audio trimmer 14.8k/月、trim audio online 1k（004）；mp3 cutter 18.1k、cut mp3 18.1k（003）
- 两个大词我们都不在 SERP 前 10，**但在场页极薄**（audiotrimmer 476 词、ezgif 276 词、rendley 190 词）＝大词有机会，排名靠域名相关性与工具本身
- Title/H1 已占位大词（Audio Trimmer — Trim a Podcast or Voice Memo / MP3 Cutter — Keep or Delete a Section）

**结论：大词不动，改写 H2 正文层**。Title/H1/URL 是占位资产（90 天计划保护层），改写对象＝正文 H2 与 FAQ——用小词簇充实，让正文承接大词进来的人。

**小词选择三过滤器**（按你的评分表精神）：
1. **真实用户语言证据**（Reddit 原话 / SERP 在场页词频）——不编造
2. **与页面真实能力匹配**（不承诺没有的功能；lossless cut / 多段不在能力内就不写）
3. **单页单意图**（trimmer/cutter 蚕食红线：trimmer=录音/播客/备忘录场景，cutter=歌曲/副歌场景，ringtone=铃声，写前先对表）

**trimmer 现成小词簇（全部有证据）**：
| 簇 | 证据 | 承接页 |
|---|---|---|
| 精度类：trim mp3 precisely / cut a specific part | Audacity 新手剪多剪少挫败（r/podcasts） | trimmer 正文（本轮已做 0.01 微调+刻度尺，正文可写） |
| 来源类：trim voice memo / trim podcast recording | VM 范式 + 定位词已有 | trimmer（既有定位） |
| 设备类：trim audio on iphone | guide 已有；SERP trimmer 簇无 App 商店 = web 承接 | trimmer + guide |
| 输出类：mp3 size for whatsapp / email attachment | 体积估算刚做 | 新内容块（议题二第 4 环） |
| 格式类：m4a for imovie / wav vs mp3 | M4A 待加；WAV 已有 | 功能先行再写 |

**改写验收**：改前按评分表打基线（trimmer 现状见议题三末尾），改后复评，目标：独特性维度是最大提分点。

## 议题二：完整意图链路承接（六环逐环盘点）

| 环节 | 页面/产品现状 | 缺口 | 动作类型 |
|---|---|---|---|
| 1. 为什么剪 | H2 "Jobs a trim actually finishes" 三场景（播客答案/副歌/备忘录） | 场景待埋点验证 | 内容维持 |
| 2. 文件从哪里来 | iPhone Files→Safari guide ✓；**文件选择器已按 accept 过滤格式**（audio/*+mp4，浏览器级过滤用户问的"帮用户过滤格式"其实已实现） | 来源指南覆盖 Android/电脑？guide 主要写 iPhone | 内容补全（低优先） |
| 3. 源格式是什么 | 投放区 "MP3, WAV, M4A, OGG, FLAC, and more" + Formats 表 ✓ | 无 | — |
| 4. 输出格式要求（平台格式/大小） | 格式下拉 + **精确体积估算**（刚做）✓ | **目标平台规格对照表缺失**：WhatsApp/微信/IG/TikTok/邮件的格式与大小上限——用户"最终目的平台"的真实约束，竞品无人系统化提供 | **新内容块（唯一高价值内容缺口）**：诚实数据表（格式×平台×上限×建议码率），随 M4A 一起落 |
| 5. 存储到哪里 | 下载即落本地；iPhone 存 Files 的 guide ✓ | 无明显缺口 | — |
| 6. 叫什么名字 | 默认 `名-edited/-clip/-trimmed` 后缀；改名随 sheet 删除 | 命名长尾无人提（Reddit 零证据） | 弱需求，不动作 |

**结论**：链路上唯一的高价值内容缺口 = **输出平台规格对照表**；其余已承接或属弱需求不动作。

## 议题三：对比头部产品的优势

**头部盘点**（SEO 对手 = mp3cut.net（123apps 系上传型）/ audiotrimmer.com（EMD 薄页）/ clideo（上传型）/ vocalremover / ezgif（薄页）；能力标杆 = LosslessCut/Audacity，桌面非 SEO 对手）：

| 维度 | 我们 vs 头部 | 判定 |
|---|---|---|
| 操作 | 零上传零注册（头部全部 upload 等待型，无一标榜本地处理）+ 双出口 + 循环试听 + 刻度尺拖动 + 内嵌微调 | ✅ 真实优势（本轮重做后实打实） |
| 能力 | 0.01s 步进精度（在线工具里稀缺，在场页无精度主张）；MP3 五档+WAV；诚实短板：无 lossless cut、无多段、无 M4A | ✅ 部分可标，短板诚实不写 |
| 差异化 | 本地处理 = 全场独一份；移动端体验 = 头部是响应式网页或要装 App | ✅ 可标榜 |

**对你提议的三项差异化分析**：
1. **"支持鼠标操作"** ✗ 不成立——所有竞品都支持鼠标，无差异。不标。
2. **"0.01s 精度快捷调节"** ✓ 成立——在线工具里真实稀缺（004：在场页无任何精度主张），且本轮已做成三列箭头组+微调。可标。
3. **"移动端全屏"** ✓✓ 强差异化——移动是 trimmer 主场景（备忘录/手机录音），头部要么响应式凑合要么要装 App；全屏沉浸式波形编辑移动 web 无人做。**建议做**（中等工作量：全屏按钮+横屏布局适配+退出手势）。

**建议标榜的三件套主张**（写进 H2/FAQ/投放区微文案）：**零上传隐私 + 0.01s 精度 + 手机上的专业手感**。

## 决定提案（待用户拍板优先级）

**内容动作（不碰保护层，改写后按评分表复评）**：
1. trimmer 正文 H2 改写：精度/来源/移动端小词簇 + 与 cutter 区隔强化
2. 新内容块：输出平台规格对照表（格式×平台×上限×建议码率，诚实数据）
3. FAQ 增补：命名/精度/移动端问题

**功能动作（独立小任务，各自验收）**：
1. M4A 导出（引擎半小时 + trimmer/cutter/ringtone 三页格式表与 product-facts 一次性同步）
2. 移动端全屏模式（差异化强项，1–2 天）

**不做**：改 Title/H1/URL（大词占位资产）；FLAC/OGG（浏览器不支持，诚实）；为标榜而标榜的"鼠标操作"。
